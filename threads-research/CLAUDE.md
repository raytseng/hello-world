# CLAUDE.md — Threads 貼文串研究工具

這個檔案是給 Claude Code 的專案說明。每次開始工作前請先讀完本檔，需要細節時再查 `docs/`。

## 專案是什麼

一個**個人使用**的 Threads 研究工具：

1. **單篇分析**：輸入一篇 Threads 貼文，收集留言，判斷貼文類型，依類型用不同的分析模式整理出有用的資訊。
2. **市調研究專案**（第二階段）：輸入關鍵字或帳號連結，找出相關貼文，分析帳號的經營重點、發文方式、語氣，以及什麼樣的貼文能讓人想回應。
3. **網頁前台**：把所有分析結果累積成可以瀏覽、搜尋、比較的報告庫。

## 必讀文件

| 文件 | 內容 |
| --- | --- |
| `docs/PRD.md` | 完整產品需求（規格的唯一依據） |
| `docs/DISCUSSION.md` | 需求討論過程與每個決定的理由 |
| `docs/IMPLEMENTATION_PLAN.md` | 開發步驟與每一步的驗收標準 |

PRD 與本檔衝突時，以 PRD 為準，並提醒使用者更新本檔。

## 已確定的關鍵決定（不要自行更改）

1. **分析引擎是 Claude Code 本身**（使用者的 Pro／Max 訂閱），第一階段**不串接 Claude API**、不需要 API 金鑰。分析流程寫成 `.claude/commands/` 裡的自訂指令。
2. **三層分工**（PRD 10.3）：能用一般程式做的（統計、字數、時間、互動指數、基本去重、明顯閒聊過濾）一律寫成程式，不交給 AI；只有需要讀懂內容的工作才由 Claude 處理。
3. **不自動擷取 Threads 網頁**：不寫爬蟲、不自動操作瀏覽器登入。資料來源是 Threads 官方 API（使用者自己的帳號授權）或手動匯入（PRD 第 7 節）。
4. **先判斷貼文類型，再決定分析方式**（PRD 第 4 節）。不要對每篇貼文都做情緒分析。
5. **收集範圍**：列舉型研究問題（「有哪些」）全量收集；比例型（「多少比例」，如情緒）以 50 則為起點逐步抽樣；總回覆數 ≤ 300 則一律全量（PRD 4.2）。
6. **內容篩選**：留言分成收錄／合併／排除；排除的留言要刪除，刪除前先統計訊號（例如「求連結」次數）（PRD 4.3）。
7. **資料與呈現分開**：分析結果存成 JSON，網頁前台讀 JSON 即時畫出報告，不產生寫死的 HTML 報告（PRD 11.1）。
8. **報告不需要 logo、不做簡報**；以網頁為主，可匯出 Markdown 與 Excel（PRD 5.5）。
9. 主題研究與帳號分析是**兩個獨立功能**；預設用**使用者自己的帳號**授權，客戶授權是選配（PRD 5.1、第 7 節）。

## 技術選擇

- 資料處理腳本：**Python 3.11+**，放在 `scripts/`。
- 網頁前台：**純 HTML + JavaScript + CSS**，放在 `site/`，不使用需要建置的框架；第三方套件從 CDN 載入。
- 資料：JSON 檔，放在 `data/`，格式定義在 `schemas/`（JSON Schema）。
- 分析模式設定：`profiles/*.yaml`（PRD 4.7）。
- 本機開啟網站：在專案根目錄執行 `python -m http.server 8000`，瀏覽 `http://localhost:8000/site/`。

## 資料夾結構

```text
threads-research/
├─ CLAUDE.md
├─ docs/                 PRD、討論紀錄、開發計畫
├─ .claude/commands/     Claude Code 自訂分析指令
├─ profiles/             各分析模式的設定檔
├─ schemas/              資料格式（JSON Schema）
├─ scripts/              收集、匯入、前處理的 Python 程式
├─ data/                 所有資料（原始資料不進 Git，見下方）

```

## 分析時必須遵守的規則

- **萃取不推測**：只記錄留言中明確寫出的內容；沒提到的欄位留空（`null`），不要自行補完。
- **每個結論都要有來源**：萃取結果與報告中的每個數字、結論，都要附上來源的 `post_id`。
- **不確定就標記**：信心低於 0.6 的分類標為「無法判斷」或「待確認」；內容篩選時不確定的預設**收錄**並標記待確認，寧可多收，不要誤刪。
- **去重不確定時不合併**：標記為「可能重複」，交給使用者決定（PRD 4.3.2）。
- **相關不等於因果**：互動驅動分析的每條「高互動公式」都要附樣本數與信心；有／沒有該特徵的任一組少於 10 篇時不列入（PRD 5.4 D）。
- **輸出要符合 schema**：寫出 JSON 前，用 `schemas/` 中對應的 schema 驗證。
- **說明樣本限制**：報告要寫明收集範圍（全量／抽樣）、收集數、覆蓋率。

## 隱私規則

- `data/**/snapshots/`（留言原文）與 `data/**/excluded/`（已排除的留言）**不進 Git**，已寫在 `.gitignore`。這樣原文到期刪除時，Git 歷史中也不會留下副本。
- 進 Git 的只有分析結果；分析結果中引用的**一般留言者一律匿名**（只有公開的品牌、創作者、媒體帳號可以列名）。
- 帳號經營分析只針對公開的品牌、創作者、媒體帳號；不推論任何人的年齡、政治傾向、健康等個人屬性。
- 網站不要部署到公開網址（PRD 11.6）。

## 溝通方式

- 使用者以**繁體中文**溝通，所有介面文字、報告內容、說明都使用繁體中文。
- 使用者不一定是工程師：說明時少用術語，必要的術語第一次出現時用一句話解釋。
- 開發時依照 `docs/IMPLEMENTATION_PLAN.md` 的步驟進行，每完成一步就對照驗收標準確認，並向使用者簡短回報。
