# 分析貼文串：$ARGUMENTS

依 `docs/PRD.md` 第 4 節分析這篇貼文串。全程使用繁體中文與使用者溝通。

## 0. 準備

- 找到資料：若 `$ARGUMENTS` 是檔案路徑就直接讀取；若是 thread_id，讀取 `data/threads/$ARGUMENTS/snapshots/` 中最新的快照。
- 若 `scripts/preprocess.py` 已存在且這份快照還沒前處理過，先執行它，並使用前處理結果（統計、預過濾、訊號計數）。

## 1. 類型判斷（PRD 4.1、4.4）

- 讀取主貼文與前 50 則回覆，判斷主要類型（M1～M6 或自訂）、次要類型（可選）、信心（0～1）與理由。
- 同時參考回覆的實際內容：貼文是提問、但回覆都是作品分享時，應判為 M1。
- **停下來向使用者確認**：說明判斷的類型、理由、將產出的內容、建議的收集範圍與預估處理量。信心 < 0.6 時列出 2～3 個候選模式讓使用者選。
- 使用者確認後，讀取對應的 `profiles/*.yaml`。

## 2. 收集範圍（PRD 4.2）

- 依模式設定的 `collection.strategy` 與總回覆數決定全量或抽樣；總回覆數 ≤ 300 一律全量。
- 若快照的資料量不足以滿足需要的範圍，告訴使用者還需要收集多少，並說明原因。

## 3. 內容篩選與去重（PRD 4.3）

- 每則留言依模式的收錄標準判斷：`include`／`merge`／`exclude`／`pending_review`。判斷時一併參考父留言與主貼文。
- 不確定（信心 < 0.6）的一律 `pending_review`（視為收錄），不要排除。
- 排除前先統計需求訊號（例如求連結、我也想要），計入對應項目的關注度。
- 排除的留言寫入 `data/threads/{thread_id}/excluded/{run_id}.json`（此資料夾不進 Git），run 結果中只保留 `post_id`、處理方式與排除原因。
- 依四個層級去重；不確定的標記為「可能重複」，不要自動合併。

## 4. 模式分析

依 profile 中的 `modules` 依序執行，萃取欄位依 profile 的 `extraction_schema`。

- **只記錄留言中明確寫出的內容**，沒提到的欄位填 `null`。
- 每個項目、數字、結論都附來源 `post_id`。

## 5. 產出

- 寫出 `data/threads/{thread_id}/runs/{run_id}.json`（`run_id` 格式：`YYYYMMDD-HHMM-{profile_id}`），內容包含：類型判斷、收集範圍與覆蓋率、內容篩選統計、模式萃取結果、分群、結論卡（3～5 張，含建議動作與信心）、摘要、研究方法與限制。
- 用 `schemas/run.schema.json` 驗證（若 schema 或驗證程式尚未建立，提醒使用者並先依 PRD 第 8 節的欄位輸出）。
- 更新 `data/index.json`。
- 一般留言者的帳號一律匿名（例如 `user_7f3a`）。

## 6. 回報

用 5～10 行向使用者回報：結論卡內容、收錄／合併／排除的數量、待確認事項（可能重複、待確認的留言），以及在網頁前台查看報告的方式。
